# Стенд в Yandex Cloud с управляемым Kubernetes

Каталог `yandex-mk8s` описывает стенд в Yandex Cloud. На машине GitLab работают GitLab CE в Docker Compose и один узел k3s. Отдельно поднимается кластер Yandex Managed Service for Kubernetes. Регистрация Runner и проект GitLab описываются в `service/runners`.

## Состав

| Ресурс | Параметры | Что ставит cloud-init |
| --- | --- | --- |
| `stand-gitlab` | 2 vCPU, 8 ГБ, диск 30 ГБ. Публичный адрес резервируется заранее через `yc`, Terraform его только читает | Docker и служба `gitlab.service`: она скачивает образ и выполняет `docker compose up` в `/srv/gitlab`. Служба `k3s-install.service` запускает официальный установщик k3s, дальше узел держит служба `k3s` |
| Кластер `stand-mk8s` | Зональный мастер, публичный адрес API, канал `REGULAR`, автообновление выключено, туннельный режим Cilium | Нет: мастер управляемый |
| Группа узлов `stand-mk8s` | Один узел, 2 vCPU, 4 ГБ, диск 64 ГБ, containerd, публичный адрес для загрузки образов. При обновлении узел заменяется на месте: `max_expansion` равен 0 | Нет: `user-data` группы узлов занят сервисом |
| Ключ KMS `stand-mk8s` | Шифрование секретов. После создания кластера ключ не меняется | — |
| Подсеть `stand` | Сеть из `network_name`, зона из `.tfenv`, `10.128.0.0/24` | — |

Сеть с именем из `network_name` уже должна существовать. По умолчанию имя — `default`. Значение задаётся в `.tfenv`. Код создаёт в ней подсеть `stand`. Новую сеть он не создаёт. Зона машины, мастера, узла и подсети задаётся переменной `zone` в `.tfenv`. Туннельный режим Cilium не резервирует в облачной сети подсети для подов и сервисов.

Порты 80, 443, 2222 и 6443 машины GitLab открыты из интернета. Порт 2222 — SSH контейнера для clone и push. Порт 6443 — API k3s. Порт 22 машины остаётся входом администратора, вход по ключу. Порты 443 и 6443 API управляемого кластера открыты из интернета.

Флаг `gitlab_letsencrypt_enabled` по умолчанию включён. Тогда `external_url` — `https://` и значение `gitlab_domain`, сертификат выпускает сам GitLab. Имя и почта `gitlab_acme_email` задаются в `.tfenv` и в репозиторий не входят. Выключенный флаг оставляет `external_url` по HTTP на публичный адрес машины, без сертификата. Порты при этом остаются открытыми.

Образ GitLab по умолчанию — `gitlab/gitlab-ce:19.5.8-ce.0`. Версия k3s по умолчанию — `v1.34.12+k3s1`. Версия Kubernetes управляемого кластера по умолчанию — `1.35`. CIDR подов управляемого кластера — `10.96.0.0/16`, CIDR сервисов — `10.112.0.0/16`. k3s оставляет свои диапазоны по умолчанию, `10.42.0.0/16` и `10.43.0.0/16`. Эти диапазоны не пересекаются между собой и с подсетью `10.128.0.0/24`.

Установщик k3s получает `--disable=traefik`: порты 80 и 443 на этой машине занимает GitLab. Параметр kubelet, включающий seccomp по умолчанию, в аргументы установщика не передаётся. В сертификат API k3s записывается публичный адрес машины. Конфигурация kubectl на машине — `/etc/rancher/k3s/k3s.yaml`.

cloud-init машины GitLab читает метаданные один раз: смена образа, ключа или скрипта на уже созданной машине требует её замены. Метаданные уже созданной машины не перезаписываются. Узлы управляемого кластера этот cloud-init не получают, поэтому запись имени GitLab во внутренний адрес на узле здесь не делается. Поды резолвят имя публичной записью DNS.

## Перед запуском

Нужны Terraform 1.0 или новее, интерфейс командной строки Yandex Cloud и открытый ключ `~/.ssh/id_ed25519.pub`. Закрытый ключ Terraform не создаёт. Другой путь к открытому ключу задаётся переменной `ssh_public_key_file`.

Провайдер читает IAM-токен из переменной окружения `YC_TOKEN`. В `.tfenv` должен быть записан вызов `yc iam create-token`: команда выполняется при `source .tfenv`, значение токена в файле не хранится. Файл авторизованного ключа не используется.

Нужно скопировать `.tfenv.example` в `.tfenv` и заполнить идентификатор облака, идентификатор каталога, имя сети, зону, имя публичного адреса GitLab, имя GitLab и почту Let's Encrypt. Файл `.tfenv` в репозиторий не входит. Идентификатор облака, идентификатор каталога, зона, имя адреса, имя GitLab и почта в репозиторий не записываются.

```bash
cp .tfenv.example .tfenv
```

Перед `terraform` в том же сеансе оболочки нужно выполнить:

```bash
source .tfenv
```

## Применение

Зона DNS внешняя, Terraform её не описывает. Сертификат выпускается при первом запуске GitLab, а cloud-init повторно не выполняется. Поэтому до машины нужно зарезервировать статический адрес. Отдельного флага «статический» у CLI нет: `yc vpc address create` создаёт зарезервированный адрес. Флаг `--deletion-protection` защищает его от удаления. Машина получает этот адрес через `nat_ip_address` и не получает динамический адрес.

После `source .tfenv` в этом каталоге нужно выполнить:

```bash
yc vpc address create --name "$TF_VAR_gitlab_address_name" --cloud-id "$TF_VAR_cloud_id" --folder-id "$TF_VAR_folder_id" --external-ipv4 zone="$TF_VAR_zone" --deletion-protection
```

Зона в команде берётся из `TF_VAR_zone`. На адрес из вывода `yc` нужно вручную создать запись `A` имени из `gitlab_domain`. К полному применению имя должно резолвиться в этот адрес. В `.tfenv` к этому моменту `gitlab_letsencrypt_enabled` должен быть равен `true`, имя и почта должны быть заполнены.

```bash
terraform init
terraform apply
```

Output `gitlab_public_ip` появляется после `apply`. До применения адрес для записи `A` нужно взять из вывода `yc`.

Состояние Terraform и файлы `*.tfvars` в репозиторий не входят. Пароль первого входа GitLab в код и в состояние не записывается: служба создаёт его на диске машины в `/srv/gitlab/.env`. Файл доступен только root. Compose подставляет переменные из него.

После применения публичный адрес GitLab лежит в output `gitlab_public_ip`. Адрес веб-интерфейса снаружи — в output `gitlab_url`. Команда входа администратора — в output `gitlab_ssh`, пользователь `ubuntu`, порт 22. Идентификатор кластера — в output `cluster_id`.

Пароль GitLab:

```bash
sudo cat /srv/gitlab/.env
```

Применение пишет два файла в каталог `kubeconfig`. В репозиторий они не входят. `terraform destroy` их удаляет.

`kubeconfig/mk8s.kubeconfig` — управляемый кластер, внешний адрес API. `kubeconfig/k3s.kubeconfig` — k3s на машине GitLab. Установщик k3s стартует отдельно от создания машины, поэтому apply ждёт файл `/etc/rancher/k3s/k3s.yaml` до 15 минут и подставляет в копию публичный адрес. Команда `yc` берёт `YC_TOKEN` из окружения после `source .tfenv`. Пути лежат в выходах `k3s_kubeconfig_path` и `mk8s_kubeconfig_path`.

## Удаление

```bash
terraform destroy
```

`terraform destroy` зарезервированный адрес GitLab не удаляет. Чтобы удалить его позже, после `source .tfenv` нужно сначала снять защиту от удаления и затем удалить адрес:

```bash
yc vpc address update --name "$TF_VAR_gitlab_address_name" --cloud-id "$TF_VAR_cloud_id" --folder-id "$TF_VAR_folder_id" --deletion-protection=false
yc vpc address delete --name "$TF_VAR_gitlab_address_name" --cloud-id "$TF_VAR_cloud_id" --folder-id "$TF_VAR_folder_id"
```
