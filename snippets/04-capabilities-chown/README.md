# Смена владельца файла без CHOWN и с ним

## Что проверяем

Два пода от root. Оба при старте создают файл `/root/artifact`. Команда проверки — `chown 1000 /root/artifact`.

У `cap-drop-pod` задано `capabilities.drop: [ALL]`. Маски в `/proc/1/status` нулевые. `chown` завершается отказом `Operation not permitted`, хотя процесс — root.

У `cap-add-pod` заданы `drop: [ALL]` и `add: [CHOWN]`. В масках `CapPrm`, `CapEff` и `CapBnd` значение `0000000000000001`. Пакет `libcap` ставится в уже запущенный контейнер, в образ он не входит. `capsh --decode` переводит эту маску в `cap_chown`, нулевую маску — в пустой набор. Та же команда `chown` проходит, владелец файла становится `1000`.

## Зачем

Показать, что `drop: [ALL]` снимает у root право смены владельца, а `add: [CHOWN]` возвращает только его. Сборке это право нужно для `COPY --chown` и `RUN chown`: без него подготовка файлов под непривилегированного пользователя образа завершается тем же отказом.
