# Просмотр сведений узла

Под `node-info` запускается от uid `0`. Под `node-info-1000` запускается от uid `1000` и gid `1000`, `runAsNonRoot: true`. Поле `privileged` не задано, том узла не задан, поле `hostUsers` не задано. Команды печатают пять файлов режима `0400`. От uid `0` они открываются. От uid `1000` ядро возвращает `Permission denied`.

| Файл | Что на узле |
| --- | --- |
| `/sys/class/dmi/id/product_uuid` | UUID машины |
| `/sys/class/dmi/id/product_serial` | серийный номер изделия |
| `/sys/class/dmi/id/board_serial` | серийный номер платы |
| `/sys/class/dmi/id/chassis_serial` | серийный номер корпуса |
| `/proc/slabinfo` | кэши slab ядра: имя, размер объекта, число живых объектов |

Команды — в [snippet.md](snippet.md). Записанный вывод — в [output.md](output.md). В показ не входит.

В `/proc/slabinfo` 173 кэша узла. Файл содержит 175 строк: строка версии и заголовок колонок кэшами не являются. Адресов и содержимого объектов нет. По имени кэша и размеру объекта видно, в какой кэш объект ядра попадёт. На этом узле у `cred_jar` размер 192 байта, общий кэш того же размера — `kmalloc-192`. Для эксплуатации переполнения в куче ядра это исходные данные. Поэтому у файла режим `0400`. В команде печатаются первые строки. Счётчики общие на узел: по ним видно, сколько задач, полномочий, inode overlay и записей таблицы соединений живо сейчас.

Проверка открытия без вывода содержимого — [dmi-userns](../dmi-userns/). Там же под с `hostUsers: false`: те же файлы дают `Permission denied`.
